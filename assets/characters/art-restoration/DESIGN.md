# 六名角色画风恢复：用户选定的 B 历史版本

唯一美术参考为 Git 提交 `aadfccb3140210730936c185ad2fc82647404dd1`。
疾风待机、前进、后退的试点已获验收；本阶段将同一方案推广至六名角色的全部 132 段动作。
疾风已验收的三段图集保持原样。未重新设计人物，也没有调用 AI 生成或补帧。

## 恢复范围与来源

`roster-source.json` 保存 B 版全部角色动作配置、42 张原始图集的 SHA-256。
原始资源来自 `../animation-v7/`；恢复前和验证时均与该 Git 提交中的 PNG 字节比较。
`ryu-source.json` 保留试点来源，供已验收的三段动作继续使用。
当前 v7 manifest 的步法配置已与历史不同，因此重建使用保存的历史配置。

身体比例、面部发型、衣服颜色、轮廓线及阴影全部来自 B 版完整绘制结果。
待机、步法、跳跃、空中拳脚、普通拳脚、蹲姿、格挡、必杀、投技、受击、倒地和起身
均使用同一历史来源，避免待机与攻击之间切换画风。
22 段原画通过当前选帧系统服务现有招式；新增招式、二段跳、冲刺、多段攻击、
格挡、反应类型和起身仍使用当前状态机与动作时序。

672 张历史原画被注册到 1092 个固定曝光档位。曝光档位不是新绘制帧：
步法仍是每方向 8 张原画、16 档曝光和 1 张停止待机；普通攻击的 12 档曝光
复用历史 8 张原画；其他动作沿用当前档位数量并复用历史原画。
脸和身体使用完整同源绘图，没有把历史头部拼在不同风格的新身体上。

## 固定像素与动作连接

`restore-historical-roster.cjs` 使用 B 版连通域裁剪及原生像素缩放，
将完整原画放入独立 PNG。疾风步法复用已验收的构建逻辑。
锚点校准只在离线图集中整体平移完整位图，不对像素、关节或身体进行变形。
没有网格变形、骨骼插值、补间或帧混合，也没有冻结上半身。
长剑、披风等越界原画使用更大的透明图格；角色比例和世界锚点不变。
待机保留历史零偏移注册与历史呼吸顺序。

恢复阶段的步法相位由身体与镜头约束后的真实位移更新，速度和步幅不变。
`support` 标明实际落地脚和触地阶段；其他角色测量真实原图的靴尖像素，
疾风保留试点的鞋底中心注册。支撑脚世界位移检查仍以每档 4.2 世界像素为界限，
容许浮点测量至 4.3。停止时保持已曝光的完整姿势再返回历史待机。

后续用户选择仅将步法动画放慢到 0.75 倍，保留世界移动速度（`walk-rate-075`）。
相位仍由真实位移推进，但增量乘以 0.75；停止收步从 12 帧延长到 16 帧。
这一选择会产生支撑脚滑动，原速的 4.2 像素界限不代表当前实时步法的结果。
`check-walk-rate.cjs` 用原图测得实时最大漂移 14.82 像素，同时核对世界位置完全未变。
原图、步幅配置、攻击、跳跃、冲刺与输入规则均保留。

普通攻击保留当前 v8 的准备、接触、回收时间表。接触档通常整体前移 1 本地像素。
闪电短拳的第二个接触档使用历史下一张伸掌原画，并整体后移 1 本地像素，
让原画手指落在当时的判定框内。恢复阶段未改变判定框或战斗端点。
显示与像素接触检查使用完全相同的 PNG 对象，没有独立的隐藏攻击图像。

后续接触漏判修复（`historical-contact-b3`）保留全部图集像素，并补充当前原画前侧拳脚
的真实攻击范围。近战检测不再用较窄的身体推挤框提前排除伸出的手臂与腿，
而是在攻击有效帧内核对双方真实不透明像素，并将命中特效放在接触处。
推挤框、前摇、有效/收招时序、格挡、招架、无敌和伤害修正规则保持不变。

## 功能保护与接触边界

当前 v7、v8 原始资源及绘制脚本保持不变，恢复资源放在本目录独立维护。
加载器验证六名角色身份、全部动作集合、历史提交和资源目录后，
将本目录配置合并到运行时目录中。三张使用该加载器的 HTML 页面更新缓存版本。

`check-historical-art.cjs` 逐像素比较全部曝光档与直接执行 Git B 版裁剪器得到的画面，
并检查 13 个战斗参数、输入、AI、UI、场景、动作采样等模块与修复前检查点字节一致。
另检查 `game.js` 除 `resolveMelee` 外、`combat-spacing.js` 除 `geometry` 外
均与检查点一致；这两个函数仅包含单独授权的接触修复。
`fighter.js` 除 `updateGait`、步法播放率常量和预览只读 getter 外与检查点一致。
不能把 `js/fighter.js`、`js/game.js` 或整个项目替换为历史版本。

`contact-contract.json` 锁定修复前 756 个有效普通攻击命中场景。
恢复阶段的 1296 个双侧、地面/空中、六档距离的真实 PNG 测试通过，旧有有效命中全部保留。
当时历史轮廓恢复后另有 32 个场景从挥空变为真实可见接触；这些边界变化如实报告，
不宣称全部命中结果与 v8 相同。伤害、硬直、攻击时序、连招修正、
冲刺及击退参数均未修改。300 像素远距离测试保持挥空，每次普通攻击最多一次伤害。

接触漏判修复的 `check-visible-strikes.cjs` 直接执行修复前提交与当前游戏：
49 个确认有真实接触的漏判场景全部修复，修复前的 788 个有效命中全部保留，
新增 109 个真实可见接触；另检查 60 组站防、蹲防、招架、无敌和训练免疫。
前摇和收招期间的接触不造成伤害。判定包围范围调整，身体推挤和数值规则不变。

## 重建和验证

使用能加载 `@napi-rs/canvas` 的 Node 环境，可设置 `NODE_PATH`。
GIF 编码需要 Pillow。运行以下命令不会写入 v7/v8 原始资源。

```sh
node scripts/restore-historical-roster.cjs
node scripts/check-historical-art.cjs
node scripts/check-stable-walk.cjs
node scripts/check-body-motion.cjs
node scripts/check-animation-consistency.cjs
node scripts/check-contact.cjs
node scripts/check-visible-strikes.cjs
node scripts/check-startup.cjs
node scripts/check-combo-balance.cjs
node scripts/check-dash.cjs
node scripts/check-double-jump.cjs
node scripts/check-ai.cjs
node scripts/render-historical-roster.cjs
python3 scripts/encode-historical-roster-gif.py
node scripts/render-contact-alignment.cjs
python3 scripts/encode-contact-alignment.py
```

旧试点构建入口 `restore-historical-locomotion.cjs` 也会调用完整构建，
不会把完整 manifest 再缩回三个动作。

步法测试涵盖全部角色、左右侧、前进/后退、30/60/120 Hz、反复启停和两侧屏幕边缘。
432 个攻击接近测试检查无伤害时不能推走静止对手；真实命中仍有击退。
原版游戏回放运行 720 个 60 Hz 逻辑帧，捕捉 240 张生产渲染帧，
覆盖三组角色的双侧移动、近身攻击、格挡、受击、二段跳、空中攻击、踢击、扫腿、投技及必杀。
GIF 半速播放并检查解码帧一致性。另在隔离的真实 Firefox 中加载全部图集、
操作键盘、测试六名角色攻击，并核对控制台错误。

验证结果、图集预览及回放保存在 `output/art-restoration/full/`，
它们是可重新生成的输出，不加入资源目录或游戏启动依赖。
不能只凭配置、帧数或语法检查认定画风修复完成。
